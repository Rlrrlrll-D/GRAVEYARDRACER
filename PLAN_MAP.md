## 0. Где мы сейчас (факты из кода, не из головы)

- **Дорога = Terrain**, нарисован **ВРУЧНУЮ в .rbxl** (Ground = полотно, Grass = обочина).
  `MapLayout.TrackSegments` (6 кубических безье, восьмёрка) — данные ТОЛЬКО для
  призраков-пейсеров, чекпоинтов и ориентации ворот. **Форма дороги (террейн) и
  данные (безье+чекпоинты) — ДВА раздельных источника, синхрон вручную.**
- Карта ~**400×300 studs** (россыпь по x∈[-202,202], z∈[-148,148]). Восьмёрка ~152 studs на петлю.
- Декор (`MapBuilder`, детерминированный RNG seed 20260717): 7 hazard-надгробий,
  10 могил-спавнов зомби (тег Grave), 6 фонарей, 10+60 мёртвых деревьев,
  россыпь 84 надгробия + 48 могил + ~496 пучков травы. **В рантайме ≈1400+ BasePart.**
- **StreamingEnabled = true.** MaxZombies = 25. Laps = 3.
- Декор-флаги уже частично правильные: трава `CanCollide/CanQuery/CanTouch/CastShadow=false`;
  россыпь надгробий/деревьев `CanCollide=true` (группа Obstacles — блокирует машину, не зомби).
- `BatManager` (сервер) уже шлёт `BatScare(origin,count,kind)` — flyby (эмбиент) и
  swarm (скример); `BatFX` рисует у клиента. Опция `jumpscares` в SettingsSchema уважается.

## 1. ГЛАВНАЯ РАЗВИЛКА: генератор дороги vs ручной террейн

Всё остальное (длина, серпантин, увеличение) упирается сюда.

### Вариант A — Генератор Terrain-дороги из `TrackSegments` (РЕКОМЕНДУЮ)
Скрипт семплит безье-полилинию и красит Terrain: полосу шириной `RoadWidth`
материалом Ground вдоль осевой, Grass вокруг (через `Terrain:FillBlock`/`FillWedge`
повёрнутыми блоками между семплами; на стыках — `FillCylinder` для гладких углов).
- **+** Форма трассы правится в ОДНОМ месте (данные) → полотно перестраивается само.
  Удлинение/серпантин/новые повороты = редактирование безье, террейн следует.
- **+** Карта становится **воспроизводимой из кода** (сейчас террейн живёт только в
  .rbxl — потеряется вместе с плейсом; git его не хранит).
- **+** Открывает вторую трассу / выбор трассы почти даром (данные-таблица).
- **−** Разовое вложение (написать+отладить генератор, подобрать ширину/сглаживание).
- **−** РАЗРУШИТ текущий ручной террейн при регенерации → делать на ветке, с флагом
  вкл/выкл, сверять с текущей формой прежде чем принять.

### Вариант B — Оставить ручной террейн
Расширять/изгибать террейн руками в Studio + править `TrackSegments`/`RaceCheckpoints` под него.
- **+** Быстрый старт, ничего не ломает сразу.
- **−** Двойной источник правды остаётся; каждый поворот — ручная перерисовка + риск рассинхрона.
- **−** Карта остаётся .rbxl-only (не в git).

**Рекомендация: A.** Юзер хочет длину + серпантин + увеличение — всё это болезненно
руками и тривиально с генератором. Генератор — фундамент под всю дальнейшую диверсификацию.

## 2. ФАЗЫ (порядок, чтобы не сломать рабочую сборку)

Каждая фаза — отдельный коммит на `feature/map`, тест в Studio, живой заезд юзера перед merge.

### Phase 1 — Генератор дороги (фундамент)
- `MapGen.lua` (модуль) или расширить `MapBuilder`: `buildRoad(segments, width)` красит
  Terrain по TrackSegments. Флаг `GameConfig.Map.GenerateRoad` (вкл/выкл, чтобы можно
  было вернуться к ручному террейну).
- Сначала воспроизвести ТЕКУЩУЮ восьмёрку генератором, сверить визуально с ручной.
- Плоское полотно (Y фикс) — высоты/холмы позже (детект чекпоинтов по X/Z, игрокам не
  ломает; призраки off, так что не парят).

### Phase 2 — Большая серпантинная трасса
- Переписать `TrackSegments` в **длинный извилистый контур**: S-повороты, шпильки,
  шикейны. Варианты формы — см. §5 (расширенная восьмёрка / полноценный круг-серпантин).
- Обновить `RaceCheckpoints` (больше чекпоинтов на длинной трассе — чтобы срез не читерился).
- Подстроить руление/скорость машины под повороты (A-Chassis: угол руля, сцепление).
- Генератор (Phase 1) красит новую форму автоматически.

### Phase 3 — Насыщение декором
- Поднять плотность россыпи (надгробия/кресты/могилы), добавить кластеры вдоль новой
  трассы и в «карманах» серпантина. Больше `Grave`-спавнов = живее зомби.
- Увеличить область карты под новую трассу (границы scatter + область стриминга).
- ВСЁ под контролем §3 (производительность): бюджет частей, флаги, инстансинг.

### Phase 4 — Зоны мышиных скримеров
- Определить **зоны-триггеры** вдоль трассы (тёмные повороты, у мавзолея/часовни,
  «вылет из-за поворота»). Данные — таблица `MapLayout.ScareZones = {{pos, radius, kind}}`.
- `BatManager`: следит за позицией машин; въезд в зону (с кулдауном) → `BatScare(swarm)`
  из точки впереди по курсу. Уважает опцию `jumpscares`. Внешний триггер
  `_G.TriggerBatSwarm` уже есть (ZombieSpawner дёргает при вылезании зомби).
- Баланс: не слишком часто (кулдаун на зону + глобальный), иначе приедается.

### Phase 5 — Проход по производительности (обязателен перед merge)
- Замер `Stats`: Instance count, draw calls, FPS ДО/ПОСЛЕ (не «на глаз»).
- Настроить `StreamingTargetRadius`/`StreamingMinRadius` под новый размер карты.
- `RenderFidelity = Automatic` на всех декор-мешах (дальние упрощаются).
- Тени только у ключевого декора (`CastShadow=false` у россыпи — уже так у травы,
  распространить на надгробия/деревья).
- Трава: 496 пучков — кандидат на прореживание/Terrain-decoration, если просядет FPS.
- Инстансинг: держать МАЛО уникальных MeshId, много копий (уже так — не плодить уникальные).

## 3. Производительность — бюджет и правила (не в ущерб)

- **StreamingEnabled уже вкл** — дальний декор не реплицируется, пока не подъедешь. Это
  главный рычаг: густое кладбище реально, вопрос настройки радиусов, а не «меньше объектов».
- Правило декора: `Anchored=true`, `CanQuery=false`, `CanTouch=false`, `CastShadow=false`;
  `CanCollide=false` кроме того, что реально должно блокировать машину (Obstacles).
- Бюджет: замерять до/после каждой досыпки. Ориентир — не раздувать draw calls
  (инстансинг мешей помогает: один MeshId рендерится пачкой).
- Зомби `MaxZombies=25` — не поднимать бездумно (AI + физика дороги).
- Динамики по минимуму: трава/эффекты — самые дорогие, их резать первыми при просадке.

## 4. Риски

- **Регенерация террейна разрушает ручную дорогу** (.rbxl, не в git) → только на ветке,
  флаг вкл/выкл, сверка формы перед принятием. Сделать бэкап плейса перед Phase 1.
- Высоты/трамплины (3D): детект чекпоинтов по X/Z (высота игнор) — игрокам не ломает; НО
  призраки семплят фикс. Y — включат призраков, нужен Y-aware `sampleAt` (сейчас Ghosts off).
- Серпантин + скорость машины: узкие повороты могут быть непроходимы на скорости —
  тюнить руление/ширину дороги вместе.
- Скримеры: перебор = приедается; кулдауны обязательны.

## 5. Варианты формы трассы (для Phase 2, юзеру на выбор)

1. **Расширенная восьмёрка** — та же топология (перекрёсток = зрелищный обгон), но
   длиннее и с S-поворотами/шпилькой на каждой петле. Минимальный передел данных.
2. **Серпантин-круг** — один длинный замкнутый контур со змейкой (несколько S подряд),
   шпильками, длинной прямой для разгона. Больше «продолжительности», нет перекрёстка.
3. **Гибрид** — большая петля с одним перекрёстком-восьмёркой + серпантинный «хвост».

Все три — это данные `TrackSegments`+`RaceCheckpoints`; с генератором (Phase 1) любая
красится автоматически. Рекомендую начать с **1 (расширенная восьмёрка)** — знакомая
топология, меньше риска, потом при желании нарастить в 2/3.
