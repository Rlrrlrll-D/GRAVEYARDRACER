# Graveyard Racer — План V2: меню, сессии, атмосфера

> Зафиксировано 2026-07-20. Большой план на будущее. Скелет кода уже лежит в репо
> (файлы помечены `[СКЕЛЕТ]`), но **ещё не подключён к Studio** — интеграция поэтапная,
> чтобы не сломать рабочую сборку.

---

## 0. Отправная точка (как есть сейчас)

- **Меню/лобби нет.** Игрок спавнится на `Workspace.SpawnLocation (28,2.6,28)`, идёт ~30 studs
  к решётке и садится в общий багги. Единственный «гейт» — фаза Idle в `RaceManager`
  (вечный `while true`), которая ждёт `MinRacers` занятых сидений.
- **После game over игрок остаётся в мире** — просто выброшен из машины, ходит по кладбищу
  до следующего заезда. Это то, что меняем.
- **Машины общие**, не привязаны к игроку; при выходе игрока клоны багги **не убираются**
  (`VehicleSpawner` без `PlayerRemoving`) → копятся.
- **Персистентности нет** (нет DataStore). `leaderstats.Zombies` живёт только сессию.
- **Дорога = Terrain** (материал Ground = трасса, Grass = обочина). Кривые Безье
  `MapLayout.TrackSegments` НЕ строят полотно — они только для пейсеров-призраков и
  ориентации ворот. Форма трассы (terrain) и её данные (безье+чекпоинты) — **два раздельных
  источника, которые надо держать в синхроне вручную.**
- Два тематических шрифта: `Bangers` (HUD) и `Creepster` (баннер "YOU WIN!").

## 1. Меню, лобби и сессионная модель (+ эвикт после game over)

**Цель:** промышленный цикл матча и «мёртвый в мире не сидит».

```
Lobby ──(готовых ≥ MinRacers)──▶ Countdown ──▶ Racing ──▶ Results ──▶ Lobby
```

- **Спавн — всегда в лобби**, не в мире (`PlayerFlow`: на `CharacterAdded` → `sendToLobby`).
  Нужен якорь `Workspace.LobbyZone` (площадка у ворот или платформа-облёт над трассой).
- **Готовность через кнопку Ready** (`LobbyUI` → `PlayerReady` remote). Гейт `MinRacers`
  переиспользуется — теперь считаем «готовых», а не «сидящих».
- **Эвикт (ключевое):** единая функция `MatchManager.evict(player, kind)` вызывается и при
  выбывании (кончились жизни, `Eliminated`), и на финише/победе. Она:
  1. глушит сиденье машины игрока;
  2. `PlayerFlow.sendToLobby` — телепорт персонажа из мира в лобби;
  3. шлёт клиенту `ReturnToLobby` → экран итога, затем лобби.
  → После заезда **в мире не остаётся никто**: ни выбывшие, ни победитель.
- **Рефактор:** вечный цикл `RaceManager` распилить на модуль **`RaceCore`** (чистая логика
  чекпоинтов/кругов/позиций, без управления фазами). `MatchManager` дёргает `RaceCore.step()`
  каждый кадр в фазе Racing. `MatchManager` **заменяет** while-цикл RaceManager — их нельзя
  запускать одновременно.
- **Владение машиной** (`PlayerFlow.assignVehicle`): багги привязан к `OwnerUserId`, убирается
  на `PlayerRemoving` → чинит накопление клонов. Открывает дорогу к выбору машины из меню.
- Новые remotes (манифест в `Net.lua`): `PlayerReady`, `LobbyState`, `ReturnToLobby`,
  `SaveSettings`, `PushSettings`, `BatScare`. `Bootstrap` должен создавать папку Remotes
  по `Net.Events` (сейчас — захардкожено).

## 2. Единая UI-тема (шрифт + палитра)

Модуль **`ReplicatedStorage.UITheme`** — единственный источник:

- **Шрифт `Creepster` (тот, что на "YOU WIN!") — везде**: заголовки, баннеры, кнопки, лейблы.
  Исключение — плотная цифирь (спидометр/таймер): там `Bangers` (`UITheme.FontNumeric`),
  т.к. Creepster на мелком кегле нечитаем. `UITheme.applyText(gui, {numeric=true})`.
- **Палитра, чередование по кругу** — `UITheme.cycleColor(i)`:
  1. `Red = (150,30,30)` — кровь / опасность / здоровье;
  2. `Green = (34,64,44)` — замшелый тёмно-зелёный (фон панелей);
  3. `Bone = (224,214,170)` — жёлтый ближе к кости (тёплый костяной, для текста/акцентов).
- **Миграция:** `UIController` и `GaugeLayout` перевести с захардкоженных цветов/шрифтов на
  `UITheme.*`. Ряды в списках/панелях красить `cycleColor(индекс)` — получаем ритмичное
  красный→зелёный→кость.

## 3. Расширение и разнообразие трассы — стоимость

Коротко: **растянуть карту и добавить поворотов — дёшево-умеренно; настоящий 3D (высоты,
трамплины) — дороже.** По осям:

| Что | Стоимость | Почему |
|---|---|---|
| Больше площади + больше декора | **Низкая по коду** | Terrain досыпать + координаты в массивы `MapLayout`. Риск — FPS от числа объектов (см. §4). |
| Новая форма/повороты (2D) | **Умеренная** | Данные — тривиально (правишь `TrackSegments` + `RaceCheckpoints`). Трение — **repaint дороги в Terrain и держать безье в синхроне** (два источника правды). |
| Высоты/холмы/трамплины (3D) | **Выше** | Terrain лепит высоты «бесплатно», И детект чекпоинтов уже по X/Z (высота игнорируется) → **гонка игроков не сломается**. НО пейсеры-призраки семплят трассу на фикс. Y=4.3 → будут парить (сейчас `GhostsEnabled=false`, так что не мешает; включат — нужен Y-aware `sampleAt`). Трамплины требуют настройки физики машины. |
| Несколько трасс + выбор в меню | **Умеренная (контент, не код)** | Обобщить `MapLayout` в таблицу `Tracks = {...}`, меню выбирает. Каждая трасса = регион terrain + набор данных. |

**Рекомендация:** снять «двойной источник правды» — сделать генератор, который **красит
дорогу в Terrain по `TrackSegments`** (ширина как параметр). Тогда форма трассы правится в
ОДНОМ месте (данные), полотно перекрашивается автоматически, синхрон гарантирован. Это
разовое вложение, которое удешевляет всю дальнейшую диверсификацию.

## 4. Плотный декор без просадки FPS

Наполнять карту густо (могилы, кресты, деревья) можно, если движок работает на нас:

- **StreamingEnabled = true** (главное). Дальний декор не реплицируется клиенту, пока не
  подъедешь. Настроить `StreamingTargetRadius`/`StreamingMinRadius` под размер карты.
- **Инстансинг мешей**: один и тот же `MeshId`+`TextureId` движок рендерит пачкой. Держать
  МАЛО уникальных ассетов, много копий — не плодить уникальные меши.
- **У всего декора**: `Anchored=true`, `CanCollide=false`, `CanQuery=false`, `CanTouch=false`,
  `CastShadow=false` (тени — дорогие; оставить только ключевым). Уже частично так.
- **LOD**: `MeshPart.RenderFidelity = Enum.RenderFidelity.Automatic` (дальние — упрощённые).
- **Меньше динамики**: трава `497` тафтов — кандидат на Terrain-decoration или на удаление
  дальних. Зомби ограничены `MaxZombies=25` — не поднимать бездумно.
- **Объединение статики**: близкий мелкий декор можно паковать в один меш/модель, чтобы
  срезать число инстансов (draw calls).
- **Правило разработки**: замерять `Stats` (Instance count, draw calls) до/после досыпки;
  цель — держать общий бюджет частей под контролем, а не «на глаз».

Итог: плотное кладбище реально без потери производительности — вопрос настройки стриминга,
инстансинга и флагов декора, а не «меньше объектов».

## 5. Летучие мыши — эмбиент + мини-скример

Модель: сервер (`BatManager`) РЕШАЕТ когда/где и шлёт `BatScare(origin, count, kind)`; рисует
рой каждый клиент (`BatFX`) у себя — дёшево, без репликации десятков движущихся моделей.

- **`flyby`** — часто (каждые 6–14 с), 1–2 мыши неспешно пролетают мимо: «кладбище живёт».
- **`swarm`** — редко (35–70 с, с шансом), 16–26 мышей **резко разлетаются в лицо** — мини-скример.
  Точки вылета — пугающие места (мёртвые деревья/мавзолей/часовня) или впереди по курсу игрока
  («вылет из-за поворота»).
- **Внешний триггер** `_G.TriggerBatSwarm(origin)` — например, `ZombieSpawner` при вылезании
  зомби рядом взмывает стаю (усиливает испуг).
- **Уважение к игроку**: опция `jumpscares` (в `SettingsSchema`). `swarm` у выключивших не
  показывается; `flyby` — безобидный, остаётся.
- **Ассеты — готовые из Creator Store/Toolbox**: положить модель в `ReplicatedStorage.Assets.Bat`
  (меш + по возможности анимация взмаха), звук писка/шелеста. `BAT_ASSET_ID`/`SCREECH_ID` в
  `BatFX` — заполнить выбранными ассетами.

## 6. Настройки и персистентность

- **`SettingsSchema`** (готов) — дефолты/типы/подписи опций; меню строится из него, сервер по
  нему же валидирует (`sanitize`).
- **`SettingsService` (сервер, TODO)** — DataStore: загрузка при входе (`PushSettings`),
  сохранение по `SaveSettings`. Туда же — статистика (убитые зомби, победы), которой сейчас
  нет.
- Клиент применяет опции: громкости → `SoundService`/группы, `cameraShake`/`jumpscares` →
  флаги в `UIController`/`BatFX`, `aimSens` → `TurretAimClient`.
- **Убрать захардкоженные громкости** (`checkpointSound.Volume`, `DrivingMusic` и т.д.) под
  общий контроль через SoundGroups, управляемые опциями.

5. **Лобби-UI:** `LobbyUI` — Ready, ростер, панель опций из схемы.
6. **Персистентность:** `SettingsService` + статы в DataStore.
7. **Мыши:** ассеты в `Assets.Bat`, включить `BatManager`+`BatFX`, настроить частоты.
8. **Карта:** генератор дороги по `TrackSegments` (снять двойной источник), StreamingEnabled,
   досыпка декора по чек-листу §4; при желании — вторая трасса + выбор в меню.

## 9. Риски / заметки

- `MatchManager` и старый `RaceManager` — **взаимоисключающие** (два контроллера фазы).
- Скелеты используют временные мосты `_G.PlayerFlow`/`_G.TriggerBatSwarm` — при интеграции
  заменить на `require`/`BindableEvent`.
- Эвикт телепортирует персонажа: на старте следующего заезда не забыть разморозить управление
  и вернуть на грид (`assignVehicle` + посадка).
- Соло-тест старта (`MinRacers=1`) остаётся валидным способом регресс-проверки цикла.
